## Preserved deviation

The first run, `34172189495`, already produced the same safe CAL abstention and valid `not_checkable` Contract C, but the research harness incorrectly expected CAL's internal verdict token itself to be `not_checkable`. The internal verdict is deliberately null; `not_checkable` is the Contract C projection. The harness was corrected to assert both layers separately.

The same reconciliation also clarified the maintained Decision HOLD reason: because proposition completion is `not_checkable`, the supported-claim policy returns `contract_c_proposition_not_checkable` before testing the reported verdict. No maintained Decision semantics were changed.

## Bounded interpretation

Across PRs #41, #42, and #43, the current maintained Decision Engine has now consumed fresh valid CAL-produced Contract C states for:

- `assessed / supported`
- `assessed / contradicted`
- `not_checkable` after safe CAL abstention

The observed Decision behavior is differentiated rather than flattened:

- supported claim -> claim verification CLEAR; deciding evidence citation CLEAR
- contradicted claim -> claim verification HOLD; exact deciding counterevidence citation CLEAR
- not-checkable claim -> claim verification HOLD with a distinct not-checkable reason; no deciding citation target exists in this case

This is a bounded state-surface result, not comprehensive Contract C coverage.

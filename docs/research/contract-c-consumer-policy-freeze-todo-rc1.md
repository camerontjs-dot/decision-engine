# Contract C Consumer Policy Freeze Gate — RC1

Do not implement broad Contract-C consumer tests until the four first consumer policies are specified independently of the candidate C schema:

1. MainFrame knowledge audit posture;
2. publication/website claim gate;
3. SOP/controlled-requirement conformance;
4. deviation/investigation decision readiness.

For each policy freeze:

- state the decision question;
- define available decision context not owned by CAL;
- define possible operational recommendations;
- define each criterion and whether unknown is distinct from failure;
- define human/authority boundary;
- define falsifying fixtures before execution.

The policies may expose that the current Gate vocabulary or runtime is insufficient. That is an intended experimental outcome.
